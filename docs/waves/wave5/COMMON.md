## Hard rules

- **Privacy first.** No new permissions, no network code in the app, no analytics, no crash reporters, no logging of typed text, words, app names or paths. Anything that would weaken this is a finding to report, not a thing to do.
- **Never touch secrets.** No keystores, passwords, API keys, tokens or private keys in the repo, in logs or in your report. Scripts read them from environment variables or paths outside the repo. Add the patterns to `.gitignore` where your brief says.
- **Do NOT run adb or emulators, and never install on a device.** A personal phone is plugged into this PC. The orchestrator does device testing. Building with Gradle and Flutter is fine.
- **Do not publish anything** (no GitHub release, no store upload, no push, no account creation, no form submission). Write the material and say what the user must do.
- **No new pub or Gradle dependencies** beyond those your brief names (name, version, licence, and a no-network confirmation in the report). Gradle plugins for Play asset packs count as a dependency; Agent C names them.
- **Contracts are read-only.** Orchestrator-owned: `pigeons/`, `lib/src/core/`, `lib/src/bridge/`, `lib/src/keyboard/**`, `lib/src/engine/**`, `lib/src/app/**` (except where a brief names a file), `pubspec.yaml`, the manifests, `android/**` except what a brief names. If you need a change there, describe it in your report with the exact patch.
- **Line endings: LF only.** Before each commit, `git diff --cached --stat` must match `--ignore-cr-at-eol`. Some older files are CRLF (`pubspec.yaml`, `pigeons/messages.dart`, `PlatformHostApiImpl.kt`, `kosha_settings.dart`): keep each file's style and do not use `sed -i` on them.
- **Quality gate**, in order, for anything that touches Dart or Android:
  1. `flutter pub get`
  2. `dart format --line-length 120 lib test pigeons`
  3. `flutter analyze` (0 issues)
  4. `flutter test` (all green; 1352 today)
  5. If you touched `android/`: `flutter build apk --debug`, then `cd android; .\gradlew.bat :app:testDebugUnitTest` (105 tests, 5 skipped), and `flutter build apk --release --split-per-abi` followed by the permission gate (Git Bash).
  Doc-only work needs no gate, but run the link and format checks your brief names.
- **Commit on your branch** (git identity preconfigured), descriptive messages, each ending with a `Co-Authored-By:` line naming your own model. Commit early and often: a usage limit may stop you. Do not merge or push.
- **Final message is your report, at most 400 words:** what you built; files touched; test results (counts); measured sizes; known gaps; what the orchestrator must check on the emulator or do by hand; requested changes to orchestrator files (as exact patches); decisions the user must make.
