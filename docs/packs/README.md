# Model packs: format, trust, signing and key rotation

Owner: Wave 5-C. Code: `android/app/src/main/kotlin/app/incogboard/keyboard/packs/`, `lib/src/packs/`,
`lib/src/app/packs/`, `tool/make_pack.dart`. Tests: `android/app/src/test/.../packs/`, `test/app/packs/`.

A pack is a signed bundle of data files: voice models, translation models, and Chinese and Japanese
dictionaries. A pack is data only. Nothing in it is executed or loaded as code. The app has no network
permission, so a pack reaches the phone in one of three ways:

1. **Import** (every flavour): the user picks a `.koshapack` file (Model packs screen).
2. **Store delivery** (`play` only): Google Play delivers an on-demand asset pack that carries the same
   `.koshapack` file (see `docs/release/asset-packs.md`).
3. Either way, the file goes through `PackStore.install`, with the same checks.

## File format (`.koshapack`)

All integers are big-endian. Format version 1 is unchanged by Wave 5.

| Bytes | Field | Notes |
|---|---|---|
| 8 | magic `KOSHAPAK` | ASCII |
| 4 | format version `1` | other values: `unsupported_version` |
| 4 | manifest length | 2 to 65536 |
| n | `manifest.json` | UTF-8, signed |
| 4 | signature length | 8 to 512 |
| m | signature | ECDSA P-256 with SHA-256, DER, over the manifest bytes |
| sum of sizes | the files | concatenated in manifest order |

`manifest.json`:

```json
{"id": "translate-en-es", "kind": "translation", "name": "English → Spanish", "version": 1,
 "languages": ["en", "es"], "engine": "opus-mt-onnx", "license": "CC-BY-4.0",
 "files": [{"path": "model/encoder.onnx", "size": 1234, "sha256": "<64 lowercase hex>"}]}
```

- `kind` is `voice`, `translation` or `dictionary`. A translation pack has exactly two languages.
- `files`: 1 to 64 entries. Paths use `/`, letters, digits, `.`, `_`, `-`, never `..` or `.`, never
  absolute, no duplicates. The names `manifest.json` and `manifest.sig` are reserved.
- The manifest lists every file's size and SHA-256. The signature covers the manifest, so the whole
  pack is covered.
- Maximum pack size: 2 GiB (`MAX_PACK_BYTES`). Free space must cover the pack plus 16 MiB.

## Key ids

A **key id** is the first 8 bytes of SHA-256 over the DER public key (SubjectPublicKeyInfo, which is what
Java's `PublicKey.encoded` returns), written as 16 lowercase hex digits. Both the app and
`make_pack.dart --key-id` compute it the same way.

The file has no key field. A pack's signer is **the trusted key that verifies its signature**, and the
app reports that key's id as `InstalledPack.signerKeyId`. This keeps the format unchanged, so packs signed
before Wave 5 still install in debug builds.

## Trust model

- `PackKeys.trusted(debuggable)` returns the release keys from `ReleasePackKeys.kt`, plus the development
  key **only when the app is debuggable** (`FLAG_DEBUGGABLE`, read in `PackStore.get`).
- `ReleasePackKeys` is a list of base64 DER public keys. While its placeholder entry is still there, release
  builds trust nothing, so no pack installs (fail closed). `ReleasePackKeysTest` fails the release gate
  (`KOSHA_RELEASE_GATE=1`) until a real key replaces the placeholder.
- The private keys are never in the repository. The development private key is at
  `%USERPROFILE%\.kosha\keys\pack-dev.pem`. The release private key is generated by the release key script
  (Wave 5-B) and kept outside the repository.
- Everything installed is re-verified when it is opened (`PackStore.open` checks the manifest signature
  against the trusted keys). A pack signed by a key that has been removed from the list stops opening, so
  removing a compromised key takes effect on the next release.
- `PackStore.check(id)` and `checkAll()` re-hash every installed file against the signed manifest and report
  counts (missing, damaged) without paths. This is the "Verify installed packs" action.
- Installs are atomic: files go to `.tmp-<id>-<nanotime>`, are hashed against the signed manifest, and only
  then renamed into place. Any failure removes the temporary folder. Tests check that nothing is left behind.

### Error codes (`PackException.code`)

| Code | Meaning | Shown as |
|---|---|---|
| `bad_signature` | not signed by a trusted key, or a file's hash does not match | "not signed for IncogBoard" |
| `bad_format` | not a pack, truncated, bad path, duplicate name, too many files, size larger than the data, bad manifest | "not a IncogBoard pack" |
| `unsupported_version` | format version other than 1 | "needs a newer version" |
| `too_large` | total file size over the limit | "too large to install" |
| `no_space` | not enough free space for the pack plus margin | "not enough free space" |

## Build, sign and verify (`tool/make_pack.dart`)

```
# build and sign (the key is required)
dart run tool/make_pack.dart --dir <staging> --id translate-en-es --kind translation \
  --name "English → Spanish" --languages en,es --engine opus-mt-onnx --license CC-BY-4.0 \
  --key <private key .pem> --out build/packs/translate-en-es.koshapack

# development packs (debug builds only): the tool refuses without --key unless this is set
set KOSHA_ALLOW_DEV_KEY=1   (and then pass --key %USERPROFILE%\.kosha\keys\pack-dev.pem, or omit --key)

# check a pack against one public key (installs nothing; exit 0 ok, 1 failed)
dart run tool/make_pack.dart --verify <pack> --pubkey <public key .pem>

# print a key's id (private or public key file)
dart run tool/make_pack.dart --key-id <key .pem>
```

The tool never prints key material. It prints the key id after signing. Without `--key`, and without
`KOSHA_ALLOW_DEV_KEY=1`, it refuses, so a release pack cannot be signed with the development key by accident.
The staging scripts (`tool/packs/**`) print the command with `--key <signing key .pem>` as a placeholder.

## Key rotation

1. Generate the new key outside the repository (release script, Wave 5-B). Keep the private key offline.
2. Export its public key: `openssl pkey -pubout -in <new.pem> -outform DER | base64 -w0`.
3. Add the base64 string to `ReleasePackKeys.KEYS_BASE64` **next to the old key**, in a release that still
   trusts the old key. Run `KOSHA_RELEASE_GATE=1 ... ReleasePackKeysTest`.
4. Sign new packs with the new key. Check each with `--verify --pubkey <new public key>`.
5. In a later release, remove the old key from the list. Packs still signed by it stop opening.
6. Compromise: remove the key in the next release, re-sign the packs with a new key, and tell users to
   re-import. Do not rely on the old key again.

The development key is never in the release list. It is trusted only in debuggable builds, so a release
APK does not trust it even though the public key constant is present in the binary.

## Bridge additions (orchestrator, Pigeon)

The Dart side (`lib/src/packs/pack_maintenance.dart`) is ready. Until these Pigeon calls exist it uses
`UnavailablePackMaintenance`, and the screen says those features are not in this build. Proposed additions
(`pigeons/messages.dart`, orchestrator-owned):

```dart
// Wave 5-C: pack maintenance
class PackCheckMessage {
  PackCheckMessage({required this.id, required this.manifestOk, required this.missingFiles, required this.damagedFiles});
  String id;
  bool manifestOk;
  int missingFiles;
  int damagedFiles;
}

class PackStorageMessage {
  PackStorageMessage({required this.freeBytes});
  int freeBytes;
}

enum PackOfferStatus { notRequested, waitingForNetwork, downloading, installing, failed, ready }

class PackOfferMessage {
  PackOfferMessage({required this.id, required this.name, required this.sizeBytes, required this.status});
  String id;
  String name;
  int sizeBytes;
  PackOfferStatus status;
}

// in AppHostApi (or PlatformHostApi for the read-only ones):
@async
List<PackCheckMessage> verifyPacks();      // PackStore.checkAll(); call off the UI thread
PackStorageMessage? packStorage();         // context.noBackupFilesDir usable space
String packDelivery();                     // 'import' (foss) or 'store' (play)
List<PackOfferMessage> packOffers();       // PackSources.forBuild(context).offers()
void requestPack(String id);               // PackSources.forBuild(context).request(id)
PackInfoMessage installDeliveredPack(String id); // DeliveredPacks.install(...) ?: throws 'not_delivered'

// PackInfoMessage gains:
//   String signerKeyId;   // InstalledPack.signerKeyId, shown in the import summary
```

Kotlin wiring for the orchestrator: `PlatformHostApiImpl` and `AppHostApiImpl` call the functions above; the
`PackSources.forBuild` one-line patch is in `packs/PackSource.kt` and `docs/release/asset-packs.md`.

Not done in Wave 5-C, and needs the bridge first: multi-select import (`importPacks(List<String>)`), a
file-size check before a large import (the SAF URI does not expose the size to Dart), and the signer key id in
the import summary.
